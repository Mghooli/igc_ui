REFERENCE DESIGN

Integration architecture

An API-led connectivity pattern for reusable banking capabilities.

API-led connectivity

Reference architecture
🖥️
Experience layerHTML / Zoho Catalyst UI
🔀
Experience APIConsumer-facing contracts
⚙️
Process APIBusiness orchestration
🔌
System APIBank adapters / connectors
🏦
Banking systemsCore banking / cards / loans
Suggested flow: the UI calls a secured MuleSoft Experience API; the Process API applies business rules and routes to System APIs; each System API adapts to the relevant core banking provider. Enforce authentication, authorization, rate limiting, input validation, idempotency, audit logging and appropriate data masking at the relevant layers.

Recommended controls

🔐
OAuth 2.0 / client policiesProtect API access and scopes.
🧾
Correlation and audit IDsTrace requests across API layers.
🔁
IdempotencyPrevent duplicate payment submissions.
🛡️
Validation and data maskingProtect sensitive customer and account data.

Suggested HTTP conventions

200 / 201Successful read or resource creation.
400 / 422Invalid fields or business rule failure.
401 / 403Authentication or authorization failure.
409 / 429 / 5xxConflict, rate limit or downstream failure.
